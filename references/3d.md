# 3D stage: stickmen, pixel-men, voxels

A built-in **software 3D renderer** (numpy + Pillow, no GPU, no extra installs). It draws flat-shaded faces far-to-near, so it is fast, deterministic and works on a weak PC. Look: neon stick figures, blocky "pixel-men", voxel text and props, optional chunky pixel-art mode.

Use a **`world3d` scene** (headline + 3D stage) or a **`stage3d` layer** inside a `motion` scene (to mix 3D with counters, shapes, particles...).

```json
{"type": "world3d", "duration": 4, "view": "three_quarter", "bloom": 0.6,
 "text": "HELLO 3D", "text_y": 0.9,
 "actors": [
   {"kind": "stickman", "x": -1.4, "motion": "walk", "color": [0, 240, 255]},
   {"kind": "pixelman", "x": 1.4, "motion": "dance", "color": [255, 46, 151], "say": "Hi!"}
 ]}
```

World: **+x right, +y up, +z towards the viewer**. 1 unit is roughly 1 metre; a character is about 1.9 units tall. Characters face +z (towards the camera) at `yaw` 0; `yaw` 90 faces right.

## Scene / layer fields

| field | meaning |
|---|---|
| `view` | camera: a preset name or an object (below). Default `three_quarter` |
| `floor` | `grid` (neon lines, default) / `checker` / `solid` / `none`; `floor_color`, `floor_ext` (size, 14), `floor_step` (1) |
| `pixel` | `0` smooth (default). `3`-`8` = **pixel-art look**: renders small and scales up with hard pixels (also faster) |
| `bloom` | `0`-`1.5` neon glow around everything in the stage (cheap) |
| `actors` | list of things in the scene (required) |
| `text`, `subtext`, `text_y`, `size`, `highlight` | `world3d` only: headline (default near the top) and a caption (bottom). Use `"text_y": 0.9` to keep the headline clear of speech bubbles |

Tip: with a 3D floor, use `bg_style` `stars`, `pixel_sky`, `none` or `aurora` on the scene - the default `grid` background draws a second grid behind the 3D floor.

## Camera `view`

Presets: `front`, `three_quarter`, `side`, `top`, `iso` (orthographic isometric - perfect with `pixel`), `orbit` (turns 30 deg/s), `push_in` (dolly in), `chase` (behind the first actor).

Or an object - every number can be keyframed or an expression (`t` = seconds in the scene, `d` = scene length):

```json
"view": {"preset": "three_quarter", "yaw": "24*sin(t*0.9)", "pitch": 13, "dist": 9.8, "fov": 38,
         "target": [0, 1.35, 0], "orbit": 0, "ortho": false, "follow": "hero", "roll": 0}
```

`dist` = distance from the target (smaller = closer). `follow` = id of an actor to keep in the middle. `orbit` = extra degrees per second.

## Actors

Common fields: `kind`, `id`, `x`, `y`, `z`, `yaw`, `scale` (all animatable: `{"from": -4, "to": 4, "dur": 3}` or `"2*sin(t)"`), `color`, `start` (seconds when it appears), `enter` (`pop` / `drop` / `spin_in` / `rise`), `enter_dur`, `say`.

### `stickman` - neon stick figure
`color`, `line_width` (0.05), `head`: `"ring"` (default) or `"solid"`. Looks best with `bloom`.

### `pixelman` - blocky character
`color` = shirt colour. `colors`: `{"skin": .., "hair": .., "shirt": .., "pants": .., "shoes": ..}`. `outline`: true/false (dark edges, default true).

### Motions (stickman and pixelman)
`idle walk run jump wave dance punch kick flip sit clap victory spin` (aliases: `stand cheer backflip boogie hello fight`).

```json
"motion": "dance"
"actions": [{"motion": "walk", "dur": 2}, {"motion": "wave", "dur": 1.5}, {"motion": "jump"}]
```
Actions run one after another with a 0.25 s blend; the last one repeats. `speed` multiplies animation speed (also per action). Feet are always kept on the floor (ground lock).

### Walking a route
```json
{"kind": "pixelman", "path": [[-4, 1], [3, 1], [3, -2]], "walk_speed": 1.5}
```
The character walks the route, turns to face the way it goes, and the leg animation is synced to the distance walked (no sliding). Without `actions` it walks while moving and idles when it stops. `walk_speed` above ~2.6 makes it run. `path_start` delays the start. Positions are `[x, z]`.

For free movement use `x`/`z` keyframes and `"face": "auto"` (turns towards its velocity and walks automatically).

### Speech bubbles
```json
"say": "Hello!"
"say": [{"text": "Hi!", "start": 1.0, "dur": 2.0}, {"text": "Let's go", "start": 3.5, "dur": 1.5}]
```
Times are scene seconds. Urdu / Hindi / Arabic text works.

### Props
| kind | fields |
|---|---|
| `cube` | `size`, `color`, `spin` (deg/s), `bob` |
| `sphere` | `size` (diameter), `color`, `bob` |
| `pyramid` | `size`, `color` |
| `tree` | `size`, `color` (leaf) |
| `platform` | `w`, `d`, `h`, `color` |
| `voxels` | pixel art extruded into blocks: `art` (rows, top to bottom), `palette` (`{"X": [255,46,151]}`), `depth` (2), `voxel` (block size, 0.12), `spin`, `bob` |
| `voxel_text` | `text` (can be 2 lines with `\n`), `size` (height), `depth` (blocks, 3), `px` (font resolution, 22: higher = finer), `colors` (1-2 colours = gradient left to right) |

`voxel_text` width is about 0.8 x `size` x number of characters - for long text lower `size` or raise the camera `dist`. Keep it under ~24 characters (it is a lot of blocks).

Voxel art example (a heart): 
```json
{"kind": "voxels", "voxel": 0.2, "depth": 2, "spin": 45, "palette": {"X": [255, 46, 151]},
 "art": [".XX..XX.", "XXXXXXXX", "XXXXXXXX", ".XXXXXX.", "..XXXX..", "...XX..."]}
```

## Recipes
- **Stick-figure explainer:** `world3d`, `view: three_quarter`, one stickman with `actions`, `say` bubbles, `bloom: 0.6`, `bg_style: stars`.
- **Pixel-art game feel:** `view: iso`, `pixel: 4`, `floor: checker`, `bg_style: pixel_sky`, pixelmen + `tree` props.
- **3D logo:** `voxel_text` with a 2-colour gradient, `view: {"yaw": "28*sin(t*0.9)"}`, `bloom: 0.55`, finish with `logo_reveal` + `hold_end: true`.
- **Crowd:** repeat actors with different `x`/`z`, `start` offsets and `motion`s.

## Performance
3D scenes cost a bit more per frame than 2D ones (a 2K frame with a few characters is still well under a second on one core). `pixel: 4` is faster than smooth. Voxel text with many characters is the heaviest thing - keep it short. `--estimate` is based on 2D frames, so for 3D-heavy videos expect it to be a little optimistic; check pacing with `--quality draft` first.

## Limits
Flat shading only (no textures, no real shadows - actors get a soft blob shadow), no imported models (FBX/OBJ/GLB), humanoid rig only (no animals / custom skeletons), faces are depth-sorted per face so very large overlapping meshes can show small sorting glitches.
